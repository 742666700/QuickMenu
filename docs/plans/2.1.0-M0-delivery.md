## 改动与原因

- **拖拽抬起**：当前模板的悬停/按压动效作用于模板内部元素，并未直接把容器的 RenderTransform 当作动画目标，因此没有证据表明现状必然报错。但原代码确实会覆盖容器已有变换，结束时也没有恢复原值。现在组合保留原变换，保存并恢复透明度、变换及原点，保留原属性来源；关闭动画时只保留拖拽透明反馈。
- **设置锚点滚动**：支持滚轮、鼠标按下、滚动条拖动、键盘、触摸接管；取消时保存当前偏移，避免移除时钟后回到零。连续点锚点、离开设置或隐藏菜单时取消旧滚动，并阻止旧完成回调重新定位。
- **关闭动画与控件反馈**：原 XAML Storyboard 没有接入 AnimationsEnabled。新增 ControlMotion，仅用于现有控件反馈：沿用原来的时间、目标值及缓动，先记录静态终态，再按策略播放有限动画；禁用、隐藏、卸载及播放完成时清理时钟。系统动画设置及渲染层级变化会刷新策略。Office 弹出菜单的 Fade 也受策略控制。
- **角色与菜单清理**：保留进场、双跳、换帧交叉淡化等既有改动；补齐角色透明度时钟清理、取消眨眼延时，避免重复眨眼。菜单隐藏时清理进场、页面、分类、状态栏、对话框、主题反馈及设置滚动时钟。
- **IconService**：共享 IImageList 的获取、GetIcon 和释放置于专用锁内，补齐已有的 COM 异常回退。显式调用 ComScope(0)，避免结构体的隐式无参初始化跳过 COM 初始化；新增并发 STA 查询、冻结图像和缓存复用测试。

没有新增界面文案，因此未修改双语 Strings 文件；没有修改角色素材、姿势、动作人设或版本号。

## 复验方法

当前运行的程序占用了默认 Release 的 exe；为保留现有进程，构建和测试使用独立输出目录，没有替换正在运行的程序。未使用 build.ps1 -Package。

在仓库根目录运行：

```powershell
dotnet build tests/QuickMenu.Fixture/QuickMenu.Fixture.csproj -c Debug --nologo
dotnet build src/QuickMenu/QuickMenu.csproj -c Release --artifacts-path artifacts/m0/build --nologo
dotnet test tests/QuickMenu.Tests/QuickMenu.Tests.csproj -c Release --artifacts-path artifacts/m0/test-build --logger 'trx;LogFileName=m0-tests.trx' --results-directory artifacts/m0/tests-final --nologo
dotnet artifacts/m0/build/bin/QuickMenu/release/QuickMenu.dll --qa --output artifacts/m0/qa-review
```

需要人工体验时，先自行从托盘退出旧程序，再启动 `artifacts/m0/build/bin/QuickMenu/release/QuickMenu.exe`；回退时退出该构建并启动原来的程序。普通启动共用现有设置文件，QA 窗口不写用户设置。

## 待人工验收与计划边界

1. 打开设置，连续点左侧锚点，在滚动中途拖滚动条、滚轮滚动或用键盘接管，确认没有回拉。
2. 桌面和置顶架长按拖拽、取消、再悬停，确认反馈正常且没有抖动或模板异常。
3. 连续呼出、切页、切分类、点角色、立即隐藏；系统关闭动画后重复，确认即时到位、不抢焦点。
4. 多显示器不同 DPI、真实手柄及触摸操作仍需本机实测。QA 的缩放截图和路由事件不能替代物理设备验证；没有修改系统动画开关来冒充实测。

计划边界与偏离说明：

- 为满足 M0 的第三项关口，增加了计划未逐项列出的 ControlMotion 控件辅助类及 Diagnostics.Motion；它们只收尾现有控件反馈，未提前实现 M1 的角色调度引擎。
- §3 的两分钟静置停表、片段内存核算以及 §8.5 的打瞌睡、性格差异等依赖后续里程碑；M0 按 §7 只验证既有改动及关闭/隐藏策略，没有把这些后续能力标成通过。
