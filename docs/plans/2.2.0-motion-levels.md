## 0. 给执行者的规则

沿用 2.1.0 计划 §0 的全部规则：代码风格跟现有代码一致，双语文案，不发布，生成物不进 `src/`，遇到计划没写清楚的地方写进交付说明。

本版另外两条：

1. **性能数据必须背靠背测**。2.1.0 的教训：对照组和候选相隔 12 小时测，对照偏高，得出了“CPU 大幅下降”的错误结论。本版每次对比都在同一时段连续跑对照和候选，每组至少测 3 轮取中位数（§7.2）。
2. **不新增美术素材**。本版只调动效的开关和强度；“全开”档的新效果全部用矢量和变换实现。

## 1. 目标与范围

**目标**

在 设置 → 外观 新增 **“动效程度”**，让不同的机器都好用：

- 低配电脑、掌机打游戏时：可以完全静态，打开菜单不额外占 CPU。
- 普通电脑：保持 2.1.0 的样子，同时把 2.1.0 超出预算的那 1–3 个点 CPU 降回来。
- 高配电脑：可以全开，粒子更多、帧率更高、AI娘更“活”。
- 默认是“自动”：按电源、掌机、系统设置自动选档。大多数人不用管。

**不在本版范围**（2.3 候选，见 §9）

- 台词气泡
- 新角色、新立绘
- 声音

## 3. 档位设计

### 3.1 五个选项

| 选项 | 一句话说明（界面上显示） | 适合 |
| --- | --- | --- |
| **自动**（默认） | 根据电源、设备和系统设置自动选择 | 大多数人 |
| **关闭** | 完全静态，打开菜单不额外占用 CPU | 低配电脑、掌机打游戏、远程桌面、不喜欢动画的人 |

说明：

- “关闭”档 AI娘 照样显示，只是一张静态图。菜单打开后，除了首次绘制以外不应再有任何重绘。
- “全开”的呼吸是 2.1.0 刻意没做的持续动画。透明窗口每帧都要软件重绘，所以只放在用户主动选择的档位里。

### 3.3 “自动”怎么选

按顺序判断，命中第一条就停：

1. Windows 关闭了“动画效果”（`SystemParameters.ClientAreaAnimation == false`）→ **关闭**
2. 软件渲染（`RenderCapability.Tier == 0`，常见于远程桌面和虚拟机）→ **关闭**
3. 呼出菜单时，前台是全屏程序（游戏）→ **轻量**
4. 开启了节电模式（`GetSystemPowerStatus` 的 `SystemStatusFlag == 1`）→ **轻量**
5. 是掌机（§3.4）并且在用电池 → **轻量**
6. 其他情况 → **标准**

“自动”**永远不会选“全开”**，全开必须用户自己选。

“自动”在每次呼出菜单时重新判断，另外在电源状态变化（`SystemEvents.PowerModeChanged`）和系统动画设置变化时也重新判断。设置里显示当前结果，例如：“自动（当前：轻量 · 使用电池）”。

### 3.4 掌机识别

满足任意一条就算掌机：

- `Win32_ComputerSystem` 的厂商或型号命中已知列表：ROG Ally（RC71L、RC72LA）、Legion Go（83E1、83L3）、MSI Claw、Steam Deck（Valve Jupiter / Galileo）、AYANEO、GPD、OneXPlayer。列表放在一个常量数组里，方便以后加。
- 主屏幕物理对角线 ≤ 9 英寸，并且有触摸屏，并且有电池。

识别结果只用于“自动”。查询要放在后台线程，结果缓存到进程结束，不能拖慢启动。

### 3.5 手动选择的优先级

- 用户手动选了某一档，就照用户的来，不受 §3.3 的条件影响。用户明确选择优先，比如有人为了性能关了 Windows 动画，但仍然想看 AI娘 动。
- 例外：手动选的档位高于“关闭”，同时 Windows 动画是关的或者在软件渲染，设置里在下拉框下面显示一行提示：“系统已关闭动画 / 正在使用软件渲染，动效可能更耗电”。只提示，不强制。

### 3.6 与“AI娘小动作”开关的关系

- 保留这个开关。它表达的是“喜不喜欢她自己乱动”，和机器性能是两回事。
- 只在“标准”和“全开”下生效；“关闭”和“轻量”下灰掉，旁边提示“当前动效档位不包含小动作”。
- 旧设置文件里没有新字段：`MotionLevel` 默认“自动”，`CharacterMotion` 保持原值。

## 5. 技术方案

### 5.1 一个策略对象替换所有开关

```csharp
public enum MotionLevel { Auto, Off, Light, Standard, Full }

// What a resolved level allows. Every place that animates asks this instead of AnimationsEnabled.
public sealed record MotionProfile(MotionLevel Level, string Reason,
    UiMotion Ui, bool ControlFeedback, bool SmoothScroll,
    AmbientMotion Ambient, double FrameRateScale, double ParticleScale, double MomentPeriodSeconds,
    bool Blink, bool Reactions, bool ReactionEffects, bool Spontaneous, double IdleIntervalScale,
    bool Loops, bool Effects, bool Breathing, TimeSpan CrossFade, ClipPreparation Clips);

public enum UiMotion { None, Fade, Standard, Rich }
public enum AmbientMotion { Still, Running }
public enum ClipPreparation { None, Reactions, All }

// Pure and WPF-free, so every rule in §3.3 is unit-tested with fake signals.
public static class MotionPolicy
{
    public static MotionProfile Resolve(MotionLevel chosen, MotionSignals signals);
}

public sealed record MotionSignals(bool SystemAnimations, int RenderTier, bool FullScreenForeground,
    bool BatterySaver, bool OnBattery, bool Handheld);
```

- `MotionPolicy` 放在 `Models/`，和 `CompanionSchedule` 一样不依赖 WPF，在 `tests/QuickMenu.Tests` 里测试：
  - §3.3 每条规则和它们的顺序
  - 手动选择优先
  - “自动”永远不出“全开”
  - 每档的参数表与 §3.2 一致
- 读取系统状态的部分放在 `Services/MotionSignalsService.cs`：电源用 P/Invoke `GetSystemPowerStatus`；全屏判断用前台窗口矩形等于所在显示器矩形，排除桌面和外壳窗口；掌机识别用 WMI，放在后台线程并缓存。
- `MainWindow` 持有当前的 `MotionProfile`，在呼出菜单、改设置、收到系统事件时重新计算。档位变了就调用 `ApplyMotionProfile()`，统一通知背景、AI娘 和控件。
- **把 17 处 `AnimationsEnabled` 全部改成查 `MotionProfile` 的具体字段**，不要留着旧属性再包一层。QA 的 `PreviewAnimations` 改成 `PreviewMotionLevel(MotionLevel)`。
- `ControlMotion.Enabled` 绑定到 `MotionProfile.ControlFeedback`。

### 5.2 各部分怎么接

- **`AmbientScene.Build`** 增加参数 `MotionProfile`：
  - 现有的 `SlowFrameRate`、`FrameRate`、`FastFrameRate` 乘以 `FrameRateScale`。
  - 粒子数量乘以 `ParticleScale`，向下取整，至少 1。
  - `MomentPeriod` 改为读 `MomentPeriodSeconds`。
  - `Still` 直接走现有的静止画面路径。
- **`CompanionWindow`**：
  - 新增 `ApplyMotion(MotionProfile)`，替代现在分散的 `StartMotion` 和 `SetSpontaneous` 判断。
  - 眨眼、反应、自发、循环、特效、呼吸各看各的字段。
  - `ClipPreparation.None` 时不调用 `pose.Prepare`，已准备的就释放；`Reactions` 时只合成 Hover 和 Click 片段。
- **呼吸（全开）**：
  - 在 `_figure` 上加一个 `ScaleTransform`，原点在脚底。
  - 播放片段、跳跃时不暂停，叠加即可。
  - 2 分钟停表时停掉；菜单隐藏时移除时钟。
- **列表依次浮现（全开）**：
  - 只在菜单进场和换页时播放，滚动时不播。
  - 每项用 `ControlMotion` 现有机制设置 `From` 透明度和 Y 偏移；最多前 12 项，其余直接到位。
  - 总时长 ≤ 300 ms。

### 5.3 把“标准”档的 CPU 降回预算

2.1.0 背靠背重测（`artifacts/acc-210/perf-209`、`perf-210`），标准档比 2.0.9 高 1.1–2.7 个百分点，超出 +1 的预算。本版要降回来。

先测量，后优化：用 `--measure-performance` 加 trace 找出多出来的 CPU 花在哪。可能的来源（按嫌疑排序，需要实测确认）：

1. 每 500 ms 一次的导演计时器：本身不重绘，但可能触发了布局。
2. 换帧交叉淡化：90 ms 内对一张完整立绘做透明度动画，透明窗口每帧都整窗重绘。
3. 片段矢量特效的时钟没有在片段结束时及时移除。
4. 2.1.0 的 M0 控件反馈：菜单显示时有没有残留的时钟。

优化之后，标准档的画面和 2.1.0 看起来要一样，不能靠砍效果达标；要砍效果的话，那是“轻量”档的事。

## 7. 验收标准

### 7.1 功能（QA 自动检查）

- 五个选项都能选，保存后重启还在；旧设置文件升级后为“自动”，`CharacterMotion` 不变。
- 每切换一次档位，以下全部立即符合 §3.2：
  - 背景是否在跑、帧率、粒子数
  - AI娘 计时器和时钟
  - 控件反馈
- **关闭**档：菜单打开 2 秒后，主窗口和 AI娘 窗口上没有任何动画时钟和计时器（眨眼也没有）；片段帧没有解码。
- **轻量**档：没有背景时钟、没有自发动作、没有循环换帧；点击 AI娘 有反应。
- **全开**档：呼吸时钟存在；隐藏菜单后全部移除。
- “自动”：用伪造的 `MotionSignals` 在 QA 里逐条验证 §3.3，界面显示的当前结果和原因正确。
- “AI娘小动作”开关在关闭和轻量档下是灰的。
- 中英文键一致（现有检查）。
- 截图：每档一张桌面截图，加上掌机尺寸（1280×800，150% 缩放）下的设置页截图。

### 7.2 性能（背靠背，每组至少 3 轮，取中位数）

用 Cream / claude（最重）、DeepSeek / deepseek-rice、Gemini / gemini 三组代表，不必七组全跑。

| 档位 | 菜单打开时 CPU（单核 = 100%） | 隐藏时 | 内存 |
| --- | --- | --- | --- |
| 关闭 | 打开 2 秒后 ≤ 0.5% | 0 | 不含片段帧，比标准档至少少 15 MB |
| 轻量 | ≤ 2.0.9 的同组数值 | 0 | 只含反应片段 |
| 标准 | ≤ 2.0.9 + 1 | 0 | ≤ 40 MB / 角色 |
| 全开 | ≤ 标准 × 2，且 ≤ 20% | 0 | ≤ 40 MB / 角色 |

- 2.0.9 对照用 `artifacts/2.1.0/control-build`，和候选在同一时段连续测。
- 比较脚本 `scripts/qa/compare_performance.py` 扩展为支持多轮取中位数和多档位。

### 7.3 用户实测清单

1. 设置里切五个档位，每档呼出几次菜单，感受区别；“关闭”档菜单应该是瞬间出现，什么都不动。
2. 笔记本拔掉电源 → “自动”应显示切到“轻量”；插上后回到“标准”。
3. 开一个全屏游戏或全屏视频，再呼出菜单 → “自动”显示“轻量 · 全屏程序”。
4. 托盘右键 → 动效程度，切换后立即生效。
5. 选“全开”，看呼吸、粒子、列表浮现是不是值得开；任务管理器里 CPU 是否能接受。
6. 有掌机的话，在掌机上用“自动”。

### 7.4 代码审查要点（我会重点看）

- 档位切换时没有残留时钟；隐藏菜单时为零。

## 8. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 17 处开关替换漏掉，某档残留动画 | QA 每档扫描主窗口和 AI娘 窗口的所有时钟（2.1.0 的 `HasMotion` 机制扩展到每档） |
| “自动”判断不准，比如把外接显示器的笔记本当成掌机 | 掌机条件要求“有电池 + 小屏 + 触摸”同时满足，或者命中型号列表；设置里显示原因，用户一眼能看出为什么，不满意可以手动选 |
| 全屏判断误伤（无边框窗口化的普通程序） | 只把“轻量”当后果，不会更差；原因写在设置里 |
| 全开档 CPU 太高 | 有硬上限（§7.2）；全开是用户主动选的，设置里说明“更耗电” |
| 标准档降不下来 | M3 先给定位报告，再决定是优化还是调整预算；不靠悄悄砍效果达标 |
| 性能数据噪声大 | 背靠背、3 轮中位数、同一时段 |
