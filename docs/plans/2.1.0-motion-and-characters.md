## 1. 目标与范围

**目标**

- 角色“活”起来：每位 AI娘 有符合人设的小动作、悬停/点击反应、长时间无操作时的状态（比如 DeepSeek娘 睡着），而不只是眨眼和统一的蹦一下。
- 人设通过**动作内容**和**节奏**两层表达：DeepSeek娘 慢半拍、Claude娘 干脆利落、Gemini娘 跳脱、ChatGPT娘 轻柔。
- 把现有动效（菜单进场、页面切换、控件反馈）收尾打磨好。
- 不变的前提：菜单打开要快，隐藏时不耗 CPU，安装包不明显变大。

**不在本版范围**（可作为 2.2 候选）

- 台词气泡（需要双语文案和排版设计）
- 新角色
- 声音
- Live2D / 骨骼动画（WPF 透明窗口里太贵）
- 持续的呼吸、漂浮动画（见 §3，代码里已经明确不做）
- 菜单的退场动画（隐藏必须即时，响应优先）

## 3. 硬性约束（每个里程碑都要满足）

角色窗口是透明窗口，WPF 用软件渲染重绘它，**动一下就重绘一整个窗口**。所以：

| 约束 | 规则 |
| --- | --- |
| 帧停留 | 换图类动画每帧至少停留 80 ms，片段平均每帧 ≥ 250 ms，循环类平均 ≥ 0.5 s。不做逐帧流畅动画。 |
| 爆发式 | 小动作是“爆发”：一个片段最长 4 s，两次自发小动作至少间隔 8 s。矢量特效沿用 `AmbientScene` 的帧率（6 / 12 fps），播完就移除时钟。 |
| 静置停表 | 菜单打开但 **2 分钟没有任何输入**：停掉所有片段和循环，只保留眨眼。DeepSeek娘 在这时停在睡着的那一帧。 |
| 隐藏为零 | 菜单隐藏后不能有任何计时器或动画时钟在跑（沿用并扩展现有的 QA 检查）。 |
| 关闭动画 | `AnimationsEnabled` 为 false（系统关闭动画、软件渲染、QA 截图）时，所有新动作不触发，显示静止姿势。 |
| 不抢焦点 | 新的反应不能激活角色窗口，也不能改变菜单的键盘焦点。 |
| 解码内存 | 单个角色同一时刻解码的图片 ≤ 40 MB（按 宽×高×4 计算，QA 里算）。只保留当前姿势的片段帧，换姿势就释放。 |
| 包体 | `Assets/Characters` 总共 ≤ 40 MB（现在 25 MB），安装包 ≤ 42 MB（2.0.8 是 26 MB）。靠 §5.2 的“补丁帧”实现。 |
| CPU | 菜单打开、角色静置时，平均 CPU 不超过 2.0.9 基线 +1%（单核 = 100%，用 `--measure-performance` 测）。采样窗口里必须至少触发一次小动作；QA 模式可以把间隔缩到 5–8 s。 |

## 5. 技术方案

### 5.1 数据模型（建议，命名可调整）

```csharp
// When a clip plays.
internal enum CompanionCue { Idle, Hover, Click, Doze, Wake, Watch, Typing }

// One picture in an animation: a whole figure, or one composed from the pose's picture and a patch (§5.2).
internal sealed record CharacterFrame(BitmapSource Picture, TimeSpan Hold);

// A short animation on a pose. Loop clips (Doze, Typing) play until their cue ends; the rest play once and
// return to the pose's own picture.
internal sealed record CharacterClip(CompanionCue Cue, IReadOnlyList<CharacterFrame> Frames, string? Effect = null,
    double Weight = 1, bool Loop = false);
```

- `CharacterPose` 增加 `Clips`。现有的 `Frames`（吃饭循环）保留原来的含义。
- `Spec` 增加对应的声明方式。编排（哪个动作用哪些帧、停多久）**留在 `Characters.cs` 里写 C#**，跟现在一样，编译期就能查错。
- `Character` 增加 `Temperament`（§4.1）。
- `Spec` 增加时段权重，例如 `Hours = [(13:00, 14:30, 3), (22:30, 06:30, 3)]`，用本机时间，可以跨午夜。

### 5.2 补丁帧：小包体、无接缝

AI 生图即使“只改眼睛”，也会让整张图的像素轻微漂移；如果直接用整帧切换，角色会抖。所以：

1. **离线合成**（工具脚本，§6.3）：
   - 输入：原图 B、生成的帧 F（已对齐到同一画布）、允许改动的区域 R（比如脸部框）。
   - 合成：C = R 内取 F，R 外取 B，边缘 12–16 px 羽化渐变。在预乘 alpha 空间混合，这样可以正确处理“擦掉”原图像素的情况。
   - 输出：裁剪出 C 中与 B 不同的最小矩形（外扩 8 px，坐标取 4 的倍数），保存成补丁 PNG。
   - 位置写进角色目录的 `patches.json`：`{ "front.yawn-1.png": { "base": "front.png", "x": 320, "y": 184 } }`。
2. **运行时合成整帧**：
   - 在 1200 px 原始空间把补丁贴回原图，再整体缩放到显示用的解码尺寸，得到一张普通的整帧 `BitmapSource`。
   - 渲染路径跟现在的吃饭循环**完全一样**（换 `_body.Source` + 交叉淡化）。不要在运行时用叠加的 `Image` 拼补丁，DPI 缩放下会出现 1 px 接缝。
   - 合成在后台线程做（冻结的位图可以跨线程）：姿势首次出现时开始，没合成完就跳过这次小动作。**姿势本身仍然同步加载**，首次显示不能变慢。
   - 换姿势时释放上一个姿势的片段帧（§3 的内存限制）。
3. **把现有素材也转成补丁**，用来验证管线并缩小包体：
   - 5 张 `front-blink.png` → 补丁，约省 5 MB。
   - `eat-2…6.png` → 基于 `eat-1.png` 的补丁。
   - 如果补丁面积超过画布的 60%，就保留整帧。

### 5.3 播放与调度

- `CompanionWindow` 增加 `PlayClip(clip)` 和一个“导演”状态机：
  - 状态：静置 → 小动作 → 静置 …；静置 → 打瞌睡（循环）→ 惊醒 → 静置；悬停/点击可以打断小动作。
  - 片段播放期间暂停眨眼，片段帧自己管眼睛。
  - 打瞌睡时不响应悬停蹦跳，有输入就先播 Wake。
  - Hover 片段冷却 4 s，避免鼠标来回划过时刷屏。
- **决策逻辑放在不依赖 WPF 的类里**（建议 `CompanionSchedule`），注入时钟和随机数，在 `tests/QuickMenu.Tests` 里写单元测试。`CompanionWindow` 只负责执行。
- **输入活动**：`MainWindow` 的键盘、鼠标移动、手柄导航都调用 `_companion.NoteActivity()`，用来重置打瞌睡计时、唤醒和 2 分钟停表。
- **姿势选择**：改成“按时段权重随机选组，不连续两次选同一组；组内随机，不重复上一次”。只有两组时，行为和现在的轮流一致。现有的 QA 检查改成“同一组不连续出现”。
- **主题时刻联动**（P2）：`AmbientScene` 在标志性时刻开始时发出 `MomentStarted` 事件。如果当前角色就是这个主题的搭档（`Character.Theme == 当前主题`），播放她的 Watch 片段。
- **搜索联动**（P2，只有 Claude娘）：搜索框有字时播 Typing 循环，清空后回原图。

### 5.4 矢量特效

Zzz、鼻涕泡、“…”打字点、“!”、汗滴、泪花、饭粒、星星爆开、光晕，**用 WPF 矢量画，不要画进位图**：

- AI 生图画文字和小符号很不稳定。
- 矢量清晰，跟主题配色，而且不占包体。

实现要求：

- 放在 `CompanionWindow` 的光点层（它本身就是一个 `AmbientScene`），沿用 Burst 的写法：12 fps，播完移除时钟。
- 锚点用立绘的比例坐标，跟 Glints 一样。
- 特效必须画在角色窗口范围内。如果需要加大 `Pad`，同步更新 `Footprint` 和 QA 里的位置检查。

### 5.5 设置

- 外观 → 新增复选框“AI娘小动作”，默认开（键名建议 `Settings.CharacterMotion`）。
- 关闭后：不做自发小动作、不打瞌睡、不联动主题时刻；悬停和点击的反应保留（这些是用户自己触发的）。
- 设置文件新增字段要兼容旧文件，沿用现有的“只重置无效字段”逻辑。

### 5.6 现有动效的强化

- M0：收尾工作区里的改动（§2）。
- 进场、悬停、点击按 `Temperament` 区分角色（§4.1）。
- 吃饭循环这类长循环，接入“2 分钟停表”。
- 主题切换、页面切换的时长统一放到一处常量里，方便以后整体调节。

## 6. 美术生产流程（ChatGPT 生图）

### 6.1 原则

1. **永远以现有立绘为底图做“局部编辑”**，不要纯文字从头生成。新整帧（比如 DS-6 举碗）也要上传原图作为角色参考。
2. **能改脸就别改手**。手指是生图的重灾区，优先设计表情、耳朵、尾巴、道具类的动作；必须动手的，验收时重点看手。
3. **画面里不要有任何文字、Logo、水印**。Zzz、“…”、“!”一律用矢量特效（§5.4）。也不要画出真实公司的 Logo。
4. **透明背景 PNG**。透明背景出不来时，用纯品红 `#FF00FF` 背景，交给脚本抠图。

### 6.2 提示词模板

补丁帧（局部编辑）：

```
[上传底图：Assets/Characters/<folder>/<base>.png]
这是一套桌面看板娘逐帧动画的基准帧。请在这张图上做局部编辑，生成同一角色的下一帧。
只修改：<部位>，改成：<具体描述>。
其他一切保持不变：画风、线稿粗细、上色方式、发型发色、服装和配饰的每个细节、身体姿势、轮廓、
画布尺寸、角色在画布中的位置和大小。
透明背景 PNG。不要加文字、Logo、水印、边框、地面阴影。不要裁剪或缩放画布。
这个表情/动作要体现她的性格：<人设一句话>。
```

整帧（新姿势）：在模板里把“只修改…”换成完整的姿势描述，并补一句“角色设计与参考图完全一致（发型、发色、服装、配饰、配色）”。

**每一帧都基于同一张底图编辑，不要拿上一张生成结果继续改。** 连续编辑会累积漂移。

### 6.3 工具脚本 `scripts/character_frames.py`

开发期工具，跟 `subset_font.py` 一样用 Python 3 + Pillow + numpy，CI 不需要运行它。

| 命令 | 作用 |
| --- | --- |
| `align <base> <generated> -o <out>` | 按需抠掉品红背景；缩放到底图高度；在 ±3% 缩放、±40 px 平移内搜索，与底图在区域外的 alpha 轮廓对齐；输出对齐后的图和对齐误差。 |
| `patch <base> <aligned> --region x,y,w,h -o <patch>` | 按 §5.2 合成、羽化、裁剪，更新 `patches.json`，报告补丁面积占比、接缝色差。 |
| `check <folder>` | 检查：整帧尺寸与透明四角；补丁在画布内、底图存在；接缝色差；边缘白边/品红残留；目录总大小。 |
| `preview <base> <frame:秒> ... -o <gif>` | 按停留时间生成预览 GIF，用于美术验收。 |

### 6.4 命名

- 补丁：`<底图名>.<动作>-<n>.png`，例如 `front.yawn-1.png`、`eat-1.doze-3.png`。
- 整帧：`<动作>-<n>.png`，例如 `offer-1.png`，画布与它所属的姿势一致。
- 原始生成图：`art-work/<folder>/`，不提交。

## 8. 验收标准

### 8.1 美术（每张新图）

1. **一致性**：100% 和 200% 缩放下看不出补丁边界；`check` 报告的接缝色差 ΔE < 3；线稿粗细和上色方式与原图一致。
2. **设计细节不丢、不变**：

   | 角色 | 必须保持 |
   | --- | --- |
   | Claude娘 | 橙色长发、黑色蝴蝶结发饰、奶油色上衣配黑领结、书、橙色裙摆和雏菊刺绣 |
   | ChatGPT娘 | 白发、两只龙角、翅膀、尾巴、小精灵、白裙 |
   | DeepSeek娘（饭碗） | 呆毛、白色女仆头饰、蓝色蝴蝶结、鳍状耳朵、鲸鱼尾、碗上的鲸鱼图案 |
   | DeepSeek娘·优雅 | 围裙上的鲸鱼图案 |
   | Gemini娘 | 猫耳、异色瞳（左右不能对调）、星星发饰、宽袖、渐变尾巴 |

3. **手**：手指数量正确，没有畸形、融合。
4. **干净**：没有文字、Logo、水印；透明边缘没有白边或品红残留。
5. **人设**：对照 §4 的角色卡和禁忌，节奏感对。比如 DeepSeek娘 的悬停反应确实“慢半拍”。

### 8.2 代码与 QA（M1 起新增的检查）

- 构建通过，全部单元测试通过（含新的 `CompanionSchedule` 测试）：
  - 时段权重
  - 不连续选同一组
  - 打瞌睡与唤醒
  - Hover 冷却
  - 设置关闭时不做自发动作
  - 2 分钟停表
- `--qa` 新增检查：
  - 补丁都在画布内，底图存在；合成后的帧与底图同尺寸。
  - 片段停留时长和总时长符合 §3。
  - 每个片段播完回到原图；片段期间不眨眼。
  - `AnimationsEnabled == false` 时不触发片段。
  - 菜单隐藏后没有计时器和时钟。
  - 单个角色解码内存 ≤ 40 MB。
  - 输出每位角色的片段条带图 `clips-<id>.png`（各帧并排，标注停留时间），供美术验收。
- 原有的立绘检查（1200 px、透明四角、纵向比例）改为检查**合成后**的帧，补丁文件本身不受这几条约束。

### 8.3 性能与包体

- `--measure-performance`：满足 §3 的 CPU 约束，并附上与 2.0.9 基线的对比。只在 M1 和 M6 各跑一次。
- `Assets/Characters` ≤ 40 MB；安装包 ≤ 42 MB。

### 8.4 每个里程碑的交付物

交给验收方的说明里要写：

1. 提交哈希和分支名（建议在 `codex/2.1.0-motion` 分支上工作，每个里程碑一个或几个提交）。
2. 改了什么、为什么；新增和修改的文件列表。
3. 自测结果：构建、单元测试、QA 报告路径（`ui-report.json`、截图、`clips-<id>.png`）。
4. 美术里程碑：每个动作的预览 GIF 路径，每张补丁的 `check` 报告。
5. 已知问题，以及偏离计划的地方。

### 8.5 用户本机实测清单（每个里程碑装好后）

1. 连续呼出菜单 10 次：姿势在轮换，不会连续两次同一组。
2. 鼠标移到角色身上、点击角色：反应符合她的性格。快速来回划过不会抽搐。
3. 菜单开着不动 30 秒：DeepSeek娘 打瞌睡，其他人做各自的“无操作”动作；动一下鼠标或按键，她会醒。
4. 用手柄在菜单里移动，也算“有操作”。
5. 开启“保持打开”，放着 2 分钟以上：动作停下，只剩眨眼，任务管理器里的 CPU 回落。
6. 切换主题、切换角色、关闭“AI娘小动作”、在系统里关闭动画效果：都表现正常。
7. 在不同缩放的显示器上打开菜单：角色清晰，换帧时没有接缝和闪烁。

## 9. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 生图前后帧不一致，角色“抖” | 区域锁定的补丁合成（§5.2）；每帧都从同一张底图编辑；M2 试点先验证 |

| 首次显示变慢 | 姿势本身同步加载，片段帧后台合成，没准备好就跳过 |
| 范围膨胀 | P2 全部可砍；M5 可整体推迟到 2.1.x |
| 人设争议 | 所有人设都是善意的粉丝向调侃；README 已有粉丝创作声明；不使用真实 Logo |
